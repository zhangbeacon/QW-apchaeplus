## 三个 Agent 的分工

| Agent | 职责 | 有什么权 | 现状 |
|---|---|---|---|
| **执行（A1）** | 生成规格、构建 V2/V3、编排打靶 | 无判定权 | **仅设计文档**，未实现 |
| **监管（A2）** | 跑阶段、诊断失败、有边界处置、审计证据 | 只有处置权 | **已实现**，demo 实跑 `verdict=PASS` |
| **评估（A3）** | 资产/漏洞评估、可复现证据、分级建议 | 只有发现与取证权 | **工具与契约已交付**，示例自检 `pass`（2 条：high 1 / low 1） |

一句话原则：**判权归机器**——漏洞是否命中、功能是否等价，由脚本退出码、探针和证据审计裁决，Agent 不自己下结论。

## 状态边界（重要）

- 执行 Agent（变体生成流水线）**尚未实现**；V2/V3 **未构建**、三版本矩阵**未运行**、HDE **没有任何数值**；
- `项目源码/supervisor/` 跑通的是 **demo 流水线**（制造一次端口冲突 → 清理重试 → PASS），**不代表真实构建/安全验证已完成**；
- `项目源码/评估Agent/scripts/` 的工具只在**示例 findings** 上自检通过，**未接真实目标**；
- 本仓库**不含**任何"安全增益 X%""抑制率 Y%""熵为 Z"之类的结论；
- 唯一可信的结论是：设计路线、判定规则、度量口径与两层组件已写死并跑通 demo，等待真实实验回填。
