# 评估 Agent · 设计说明

## 1. 角色分工

评估工作天然是「一部分人拿主意，一部分人干活」，因此拆成两类角色，与监管/生成/裁决的分层一致：

| 角色 | 职责 | 禁止 |
|---|---|---|
| **决策 Agent**（1 个） | 定方向、拆意图、判定证据是否成立、写 finding | 不亲自执行探测动作 |
| **执行 Agent**（N 个，可并发） | 按意图做单一方向的探测与取证，实时把结论写回父意图 | 不自行扩大范围、不自行判定等级、不调用写操作 |
| **取证器**（脚本） | 报文构造、浏览器流量捕获、证据自检 | 不含业务判断 |

决策 Agent 是唯一的“拍板者”，执行 Agent 之间互不依赖，可并行。

## 2. 探索链路

```text
goal（目标 + 范围 + 授权）
  └─ spawns → intent（要验证什么）
       └─ yields → fact（已观测到的事实）
            └─ derived_from → intent（由事实推导的新意图）
                 └─ proves → finding（可复现的漏洞结论）
```

规则：

1. **intent 必须有明确验证方法**；同目标、同范围、同方法的意图只保留一个，避免重复探测；
2. **fact 是观测，不是结论**——`端口开放` 是 fact，`未授权可读数据` 才是 finding；
3. **finding 必须挂 intent**，否则无法回溯是哪次探测证实的；
4. 新事实可以派生新意图，也可以直接结案；证据不足时扩展侦察或换方向。

## 3. 证据纪律

| 要求 | 说明 |
|---|---|
| 可复现 | 每条 finding 至少一条有序步骤：命令、HTTP 报文或操作序列；报文字段必须逐字节可用 |
| 可观测 | 步骤后附观测结果（状态码、响应片段、字段名），脱敏后入库 |
| 可回溯 | 步骤与 fact 双向可查：fact 指向产生它的 intent，finding 指向证实它的 intent |
| 最小化 | 命中样例只取 2 条，姓名/手机/证件号等脱敏；不批量导出 |
| 只读优先 | 写操作、删除、短信/邮件触发一律禁止；确需验证写路径时先取得明确授权并留档 |

## 4. 漏洞优先级

按“真实攻击者能否获得收益”排序，而不是按数量：

- **严重**：可直接控制服务器、获取管理员权限、批量敏感数据泄露、关键业务逻辑绕过；
- **高危**：未授权访问、越权（水平/垂直）、注入、命令执行、文件上传导致 RCE、SSRF 触达内网；
- **中危**：需额外前置条件、但有明确利用路径；
- **低危/信息**：配置缺陷、信息暴露、版本泄露——仅在可作为攻击链一环时保留。

“存在但无法利用”“需要极端条件”的问题不作为 finding 输出，最多记为 fact。

## 5. 复现格式（Burp 报文）

Web 类漏洞统一以原始 HTTP 报文呈现，保证可粘贴复现：

```
POST /path HTTP/1.1
Host: target.example
Content-Type: application/json
<auth-header>: <value>
Content-Length: <n>

<body>
```

要求：

- 报文中的认证值、密文、Cookie 必须与实测一致；
- `Content-Length` 与实际 body 字节数严格相等（常见失败点）；
- 需要前置步骤时，按 `报文① → 报文②` 顺序给出，并标注每一步的产物（token、Cookie）；
- 响应给出**解密后**的关键字段（脱敏），便于核对。

## 6. 自检（交付前）

`scripts/evidence_lint.py` 会检查：

1. 每条 finding 是否有 `title`、`severity`、`description`；
2. `reproducibleSteps` 是否非空、每条是否包含可执行动作；
3. `severity` 是否在枚举内；
4. 是否存在重复 finding（同 target + 同 title）；
5. 汇总输出 `assessment.json`：`verdict`、`counts`、`top_risks`。

任一项不通过 → `verdict=fail`，不得进入裁决。

## 7. 边界

- 授权范围外不探测；范围以 `assessment.config.json` 的 `scope` 为准；
- 不执行破坏性动作（写、删、改密、取消业务单据）；
- 不把真实目标数据写进仓库：示例与测试一律用占位目标；
- LLM 仅用于归纳与排序建议，不生成 finding 结论本身。
