# 把 A1 接进流水线

> 这份示例只演示**输入形状与调用顺序**，数值是占位，不是实验结果。

## 1. 准备输入

| 输入 | 从哪来 | 放哪 |
|---|---|---|
| `plan.yaml` | 复制 `项目源码/执行Agent/plans/hde12.yaml`，改 `base.source` 与候选表 | `项目源码/执行Agent/plans/` |
| 源码包 | 你的被测程序（带 sha256） | 计划里 `base.source.package` 指向的路径 |
| 分数 JSON | A3 评估 Agent 产出 | `artifacts/<run_id>/hde.json` |

`plan.yaml` 最少要改三处：`base.source.package`、`base.source.sha256`、`candidates[].role` 里谁是 `BASELINE`。

## 2. 调用顺序

```bash
cd 项目源码/执行Agent

# 1) 校验（重复 id / 缺字段 / 非法轴 都会在这里失败）
PYTHONPATH=src python3 -m qw9 gen plan --plan plans/hde12.yaml

# 2) 展开配方（每候选一份 recipe + runtime.json）
PYTHONPATH=src python3 -m qw9 gen expand --plan plans/hde12.yaml --run-id gen01

# 3) 构建（可先只建基线，确认环境没问题）
PYTHONPATH=src python3 -m qw9 gen build --run-id gen01 --jobs 4 --only c1
PYTHONPATH=src python3 -m qw9 gen build --run-id gen01 --jobs 4

# 4) 完整性自检
PYTHONPATH=src python3 -m qw9 gen verify --run-id gen01

# 5) 拿到分数后挑 V2 / 预注册 V3
PYTHONPATH=src python3 -m qw9 gen deliver --run-id gen01 --scores artifacts/gen01/hde.json
```

## 3. 分数文件长什么样

见 [scores.example.json](scores.example.json)：

```json
{"schema": "qw9/scores/v1", "run_id": "gen01",
 "candidates": {"c1": {"score": "N/A"},
                "c3": {"score": 0.71, "detail": {"hde": 0.42, "per_cve": {}}}}}
```

规则：`"N/A"` = 无有效分，不参与挑选；`detail` 是选择理由唯一合法溯源目标。

## 4. 拿到什么

| 产物 | 位置 | 用途 |
|---|---|---|
| 逐候选构建 | `artifacts/gen01/<id>/{manifest.json,build.log,runtime.json}` | 交给 A3 打靶、给 A2 审计 |
| 自检结果 | `artifacts/gen01/verify.json` | "建造是否有效"的凭据 |
| 交付目录 | `delivery/gen01/{V2,V3}/` | 最终交付的变体 |
| 选择理由 | `delivery/gen01/V2/selection.md` | 答辩时解释"为什么是它" |
| 溯源清单 | `delivery/gen01/traceability.json` | 计划→配方→产物→分数 全链哈希 |

## 5. 两个注意

1. **不要改分数文件**：`deliver` 只读它，改了就破坏溯源哈希；
2. **与 A2 尚未联调**：当前 A1 是独立命令族，`journal.jsonl` 申请单写盘已有，但还没接成"申请→放行→构建"的自动循环。

> demo01 用的是 `demo-target/` 里的**合成靶标**，只验证流水线本身；换真实目标时请从 `plan` 校验重新走一遍。
